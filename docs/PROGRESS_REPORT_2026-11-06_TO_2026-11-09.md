# ContractFlow — progress report, Friday 6 to Monday 9 November 2026

## Summary

Over four days the UI/UX remediation plan in `docs/UI_UX_ASSESSMENT.md` moved from Phase 1 through to the end of Phase 3.

- **Phase 1 (critical usability fixes):** complete and merged (PRs #67 and #68).
- **Phase 2 (design system and visual consistency):** started in PR #69, completed in the working tree.
- **Phase 3 (navigation and workflows):** all seven roadmap items worked through. Two have open follow-ups that need a product or engineering decision:
  - UX-16 (onboarding) was simplified in the UI only; deferring legal details needs a product decision.
  - UX-05 (password reset) works, but a per-IP rate limit is still open.

Three pieces of new backend capability were added along the way. Each one was approved before it was built:

- **Password reset:** a full forgot/reset flow, with a new database table.
- **Counterparties:** the contract list now shows the other parties to each contract.
- **"Assigned to me":** a filter that narrows the contract list to contracts the user holds a role on.

**Most of this work is not committed yet.** Everything after PR #69 (about 130 changed or new files) is uncommitted on branch `ui-remeditaion-phase3`. It has been tested, but it still needs a commit and a pull request.

## 2. Uncommitted work (branch `ui-remeditaion-phase3`)

Each item below was tested and checked in a real browser before being marked done.

### Phase 2 — completed
- **Design tokens (DS-07):**
  - one type scale;
  - consistent corner radii;
  - a standard 40px control height inside `packages/ui`.
- **Colours (DS-06):** hard-coded palette colours replaced with semantic tokens, with an automated check.
- **Shared sign-in layout (DS-05):** `AuthHero` and a page header with a proper `<h1>` (A11Y-02) used across the auth screens.
- **Native checkboxes replaced (DS-09):** they now use the shared accessible checkbox. Inputs have visible borders (A11Y-03).

### Phase 3 item 1 — one app shell (DS-04, A11Y-06)
- The company area and the platform admin area now use one shared `AppShell`, built on the shared sidebar.
- The admin mobile menu is now a proper drawer: it traps focus, closes with Escape and is announced as a dialog. Before, it had none of these.

### Phase 3 item 2 — account menu (UX-17)
- The account menu was only "Sign out". It is now a full menu, shared by both areas, with an admin link for platform administrators.

### Phase 3 item 3 — contract creation rebuild (UX-04, TECH-04, TECH-05)
- **Four steps** instead of 20 flat fields: Basics → Parties & workspaces → Commercial terms → Dates.
- **Natural units:**
  - money is entered as a normal decimal amount (for example 1,500,000.50) and converted exactly, using the currency's own decimals;
  - rates are entered as percentages rather than basis points;
  - the time zone is chosen from a list.
- **Validation:**
  - each step is checked before moving on, and Enter moves to the next step;
  - focus goes to the first problem;
  - after creating, the user is taken to the new contract with a confirmation.
- **Two bugs found and fixed during browser testing:**
  - Enter did nothing in the form;
  - on desktop, an error appearing could swallow the Next click.
- **Permission check (TECH-05):** creation is now offered based on the same administrator flag the server uses.

### Phase 3 item 4 — contract detail and contract list (UX-13, UX-14)
- **Contract detail:** tabs for Overview, Parties, Roles, Sites, Signatories and History, each with its own address and with focus handled correctly.
- **Contract list:**
  - heading before the create action;
  - search as you type (server-side), a status filter and sorting;
  - a responsive table on desktop and cards on phones;
  - separate loading, error and empty states;
  - the archived view relabelled to say what it actually shows ("archived contracts only").
- **Counterparties (approved API change):** the list now shows the other companies on each contract, under the same visibility rule as the contract's Parties tab. An integration test confirms no other company's data leaks.

### Phase 3 item 5 — authentication screens (UX-07, UX-08, UX-09, UX-10, UX-18)
- **Login:**
  - show/hide password;
  - a clear message and a resend link for unverified accounts;
  - focus moves to errors, and duplicate submits are prevented.
- **Registration:**
  - the terms open in a dialog, so the form isn't lost;
  - the misleading "Step 1 of 4" badge is gone;
  - mismatched passwords are reported straight away.
- **Verification page:** shows which (masked) address the email went to, and pre-fills the resend form. The address is kept in the browser tab only, never in the URL.
- **Expired session:**
  - the user is sent to sign in with "Your session has expired" and returned to the page they were on afterwards;
  - the redirect happens only once;
  - no stale data is left on screen.

### UX-05 — forgot and reset password (approved backend work)
- **Backend:**
  - new `password_reset_token` table (migration `1793400000000`) that stores only a hash of each token;
  - `POST /auth/forgot-password` and `POST /auth/reset-password`.
- **Security:**
  - single-use links that expire after 30 minutes;
  - only the newest link works;
  - the same answer whether or not the account exists, in both wording and timing;
  - a per-account rate limit;
  - resetting signs the account out on every device;
  - the token is removed from the browser address bar as soon as the page loads;
  - two simultaneous attempts with the same link: only one can succeed.
- **New pages:** "Forgot your password?" and "Choose a new password", plus a link from login.

### Phase 3 item 6 — onboarding (UX-16, UI only)
- Company creation is now three short steps instead of 13 fields at once, with a full-width layout.
- A clear note tells invited users they don't need to create a company.
- **Bug fixed:** the old "Sign out" link didn't actually sign the user out. It now does.

### Phase 3 item 7 — My contracts (approved API change)
- **New member landing page, "My Contracts":** lists only the contracts the user holds a role on, with their role and workspace on each one.
- **API change:** an "assigned to me" filter on the existing contract list. It only narrows results within the user's company and gives no extra access.
- **Verified:**
  - a company administrator with no roles sees an empty state, not every contract;
  - switching company shows only that company's contracts.
